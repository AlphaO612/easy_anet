# Регистрация узла и ревизии межсерверных проб

Все пути API указаны относительно `/api/v1`. Для удалённого подключения используйте HTTPS.

1. Создайте узел в админке. Администратор вызывает `POST /servers/{id}/invitations` с bearer-токеном. Ответ содержит `node_id` и `token`. Приглашение действует 15 минут. Повторная выдача заменяет приглашение.
2. Доверенный установщик узла вызывает `POST /control/nodes/{id}/enroll` с заголовком `X-Enrollment-Token`. Сохраните полученные поля в `[control_plane]` как `node_id` и `token`, задайте `url` панели. При утрате ответа выпустите новое приглашение. Успешный обмен заменяет постоянный ключ узла. Действующие ключи и приглашения можно отозвать ротацией через панель.
3. Создайте отдельную пару Ed25519 командой `anet-keygen server`. Для auth передайте файл с Base64 закрытым seed через `ANET_PROBE_SIGNING_KEY_FILE`. При установке вручную доступна переменная `ANET_PROBE_SIGNING_KEY`. Для ноды поместите Base64 открытого ключа в `control_plane.probe_signing_public_key`.

Пример дополнительных полей существующей секции `[control_plane]`:

```toml
probe_targets_dir = "/var/lib/anet/probes"
probe_signing_public_key = "<Base64 открытого ключа панели>"
probe_allowed_targets = ["exit.example.org:443", "https://exit.example.org/health"]
```

Смонтируйте каталог целей в контейнер сервера на запись и в Prometheus agent на чтение. Каталог принадлежит UID процесса сервера, рекомендуемый режим 0755. В нём сохраняются подписанная ревизия и `targets.yml`. После замены ключа панели оператор проверяет новый открытый ключ и переинициализирует локальную контрольную запись `.anet-probe-revision.json`.

| Запрос | Результат |
| --- | --- |
| `GET /servers/{id}/probe-revision` | Администратор получает желаемую и применённую ревизии, последнюю ошибку и подписанный манифест. |
| `PUT /servers/{id}/probe-revision` | JSON с `base_revision` и `edges`. Каждая цель задаёт UUID зарегистрированного `target_node`, `module` и точный `target`. Разрешены `tcp_connect` для host:port и `https_ready` для HTTPS URL. Конфликт с параллельной публикацией возвращает 409. Пустой список прекращает пробы. |
| `GET /servers/{id}/probe-history` | Администратор получает последние 50 подписанных публикаций с автором и временем. Для следующей страницы передайте номер последней ревизии в параметре `before`. |
| `GET /control/nodes/{id}/probe-revision` | Узел забирает подписанную ревизию по исходящему соединению, проверяет подпись, адресата, монотонность номера и локальный список разрешённых адресов. |
| `POST /control/nodes/{id}/probe-revision/result` | Узел подтверждает атомарную запись файла целей или сообщает ошибку. Устаревшее подтверждение получает 409. Prometheus подхватывает файл независимо, свежесть измерений видна по метрикам. |

При недоступности панели Prometheus продолжает читать локальную конфигурацию. Для отката опубликуйте предыдущий набор целей с текущим базовым номером.
