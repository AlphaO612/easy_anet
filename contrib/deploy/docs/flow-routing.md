## Выбор выхода для новых IPv4-соединений

Для каждого профиля используйте выделенный Compose-проект с собственным входным сервером, ключами и сетью. Файл привязок задаёт опубликованный профиль, пользователя, группы, входную подсеть и интерфейсы разрешённых путей. Пример для двух заранее настроенных выходных серверов:

```json
{"profile":"home","user":"alice","groups":[],"source":"10.77.0.0/24","paths":{"west":{"interface":"anet-up1","table":1001,"config":"/private/west.toml"},"north":{"interface":"anet-up2","table":1002,"config":"/private/north.toml"}}}
```

В каждом конфиге uplink задайте manual_routing=true и соответствующий tun_name в секции main. Используйте разные туннельные подсети на выходах. Для опубликованного прямого пути вместо config укажите gateway и интерфейс выделенной сети выхода.

1. Соберите обновлённый образ сетевого помощника из contrib/docker/Dockerfile.netns.
2. Сгенерируйте overlay командой `python3.11 flow-compose.py /private/binding.json > /private/flow.json`. Запустите базовый compose.yaml с этим overlay, задав SERVER_IMAGE, CLIENT_IMAGE, NETNS_IMAGE и STATE_DIR.
3. На хосте rootless Docker запустите `python3 flow-router.py NAME_OF_NETWORK_CONTAINER /private/binding.json --api https://panel.example/api/v1 --token-file /private/admin-token`. Токен читается на хосте. После завершения административной сессии файл требует обновления.
4. Контроллер применяет актуальную политику по данным опубликованной топологии и свежих проб. Выход сохраняется в conntrack для существующего соединения. После истечения срока наблюдения передача по соответствующему пути прекращается. Решения по правилам и номер ревизии пишутся в stdout.

Для доменных условий нужны наблюдаемые DNS-ответы в dns_answers (address, domain, expires в Unix seconds) в файле привязок. Для автоматического сбора добавьте в привязку dns_listen (локальный адрес входного TUN), dns_upstream (IPv4 доверенного рекурсивного DNS), dns_path (разрешённый путь для запросов к этому резолверу) и dns_answers_file (абсолютный путь к answers.json в отдельном каталоге с правами 0700, принадлежащем пользователю rootless Docker). Соберите DNS_IMAGE командой `docker build -t anet-profile-dns:local contrib/deploy/profile-dns`, передайте этот образ при генерации и запуске overlay и укажите dns_listen как DNS в клиентском профиле. Измеряются A-ответы для запросов данного профиля через этот DNS, с минимальным TTL всей цепочки CNAME. Внешние DoH-запросы клиента останутся неизвестными. Настройка dns_upstream определяет, куда сам вход отправляет DNS-запросы. Вход через WireGuard/VLESS проверяется отдельным профилем цепочки. Перед изменением соответствия таблиц интерфейсам пересоздайте выделенное сетевое пространство, чтобы освободить старые conntrack-записи.
