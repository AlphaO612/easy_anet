# Маршрутизация 5 → 2 и профильный DNS

На одном физическом компьютере с WSL2, ядром Linux 6.18.58.1, nftables 1.0.2, Python 3.10.12, dnspython 2.1.0 и DiG 9.18.39 проверены TCP и UDP. Скрипт поднимает 13 сетевых пространств имён внутри временного user namespace. Пять клиентов подключены к пяти входам. Каждый вход имеет два независимых veth до каждого из двух выходов и отдельную прямую связь с приёмником. Выходы выполняют SNAT с адресами 198.18.0.1 и 198.18.1.1. Проекты Docker, ключи и внешние адреса для этого теста не нужны.

Из корня репозитория выполните команду под обычным пользователем Linux с разрешёнными непривилегированными пространствами имён. Нужны iproute2, nftables, util-linux, dig и Python с dnspython.

```sh
PYTHONDONTWRITEBYTECODE=1 python3 contrib/deploy/tests/test_netns_matrix.py
```

В таблице приведён результат для новых TCP- и UDP-потоков. Для каждой строки выполнено по одной попытке обоих типов от каждого клиента при каждой из четырёх стратегий, всего 200 попыток. Приёмник возвращает наблюдаемый адрес выхода. Счётчики nft на выходах независимо показывают использованный uplink. При ожидаемом запрете тест дополнительно проверяет отсутствие маркера запроса в журнале приёмника.

| Состояние | strict-ip | prefer-route | speed | auto |
| --- | --- | --- | --- | --- |
| Оба выхода доступны | Первый выход | Первый выход | Первый выход | Первый выход |
| Первый uplink первого входа выключен | Запасной uplink к тому же выходу | То же | То же | То же |
| Оба uplink к первому выходу выключены для всех входов | Запрет на всех входах | Второй выход | Второй выход | Второй выход |
| Оба выхода недоступны, прямой маршрут остаётся | Запрет на всех входах | То же | То же | То же |
| Связность восстановлена после полного отказа | Первый выход | Первый выход | Первый выход | Первый выход |

Для проверки действующих соединений скрипт изменяет разрешённый выход. Открытый TCP-сеанс и прежняя UDP-пара адресов и портов сохраняют первоначальный SNAT, новый поток получает второй адрес. Отзыв наблюдения первоначального пути прекращает передачу закреплённого UDP-потока.

Клиент вызывает `dig` через исходный сервис `profile-dns/server.py` по UDP и TCP. Локальный upstream отвечает A-записью с TTL 25 секунд и записывает фактический адрес отправителя. Проверяются три независимых результата — адрес DNS-выхода у upstream, ответ у клиента и срок в файле наблюдений. Доменное правило разрешает новый поток через второй выход после первого ответа. После ответа на второе имя с тем же IP неоднозначное соответствие блокирует новый поток. Отзыв наблюдения DNS-пути блокирует запрос и сохраняет журнал upstream без тестового имени.

Для каждого отказа скрипт выключает интерфейсы на стороне выхода и считывает состояние carrier на каждом входе. Контроллер использует эту доступность с фиксированными значениями пропускной способности, RTT и потерь. Протокол покрывает реальную маршрутизацию IPv4, conntrack, жизненный цикл DNS-наблюдений и правила nft. Прогоны через зашифрованные ANet-транспорты и Prometheus на разных VPS требуют отдельных результатов. Скрипт завершает фоновые процессы, временный каталог и сетевые пространства удаляются при выходе.
