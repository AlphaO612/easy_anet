Для повторения на изолированной установке укажите доступные на стенде образы CLIENT_IMAGE, NETNS_IMAGE и PYTHON_IMAGE. Последний должен содержать Python 3. Передайте имя Compose-проекта, выданный профиль и его точный QUIC-адрес.

```sh
python3 contrib/deploy/tests/installed_tunnel.py "$COMPOSE_PROJECT_NAME" /private/client.toml quic://localhost:47261
```

[Проверка установленного сервера](installed_tunnel.py) подключает клиент к приватному bridge проекта. Во временной копии TOML тест заменяет localhost и опубликованный порт адресом сервера внутри bridge и включает ручную маршрутизацию. Сервис в той же сети проверяет случайные данные и исходящий адрес. Этим прогоном проверены реквизиты, туннель, TCP/UDP и NAT на установленном сервере. Публичный firewall и физический iPhone проверялись отдельно.

## Чистая KVM и обновление поставки

На отдельной amd64 KVM с Debian 12, гостевым диском 65 ГБ и 5 ГБ RAM shell-установщик подготовил rootless Docker 29.10.0. Compose 5.8.0. На этом госте shell установил standalone-выход и Ansible установил новый проект anet-easy из комплекта 8715d02. Playbook завершился с ok=10, failed=0, unreachable=0. Выданный WireGuard peer на приватном bridge передал TCP и UDP через вход, ANet uplink и выход до echo-сервиса. Для обоих протоколов приёмник вернул исходную строку и адрес выходного namespace 172.19.0.2.

Проверка обнаружила, что у Grafana и Prometheus на Docker 29.10 запрошенные loopback-привязки отсутствовали в NetworkSettings.Ports. В 761eb81 оба сервиса получили доступ к сети панели. После пересоздания проверены HTTP `/-/ready` и `/api/health` на опубликованных портах. Установщик проверяет их перед завершением. На первом запуске Grafana выполнила 679 миграций.

Экспертный shell-мастер в режиме build с `--config` сформировал проекты всех трёх профилей в отдельных каталогах. Установщик отклонил незакреплённый XRAY_IMAGE до создания состояния. Для этих проверок использованы Docker Compose 2.23 и Python 3.10 в WSL. Полную проверку TOML выполняет Python 3.11+ в госте.
