# Приёмка клиентского профиля на linux/amd64

В Linux-контексте rootless Docker нужны OpenSSL, Python 3 и локальные образы сервера, CLI-клиента и сетевого помощника. Сервер читает `/etc/anet/server.toml`, entrypoint образа клиента принимает `-c FILE`. Тест создаёт временную bridge-сеть, генерирует одноразовые ключи и запускает проверку. Тестовые порты доступны только внутри этой сети.

```sh
SERVER_IMAGE=anet-server:accept CLIENT_IMAGE=anet-client:accept NETNS_IMAGE=anet-netns:local \
    python3 contrib/deploy/tests/tunnel.py accept
```

Проверка связывает тестовые сокеты с интерфейсом клиента и передаёт случайную строку отдельному echo-сервису через QUIC. Приёмка проходит, если по TCP и UDP возвращаются исходная строка и адрес выхода серверного узла, а после перезапуска сервера результат повторяется. Переменная `PYTHON_IMAGE` позволяет выбрать зеркало образа для запуска echo и проб.

## Приёмка этапа 3 на Debian 13, linux/amd64

Стенд работал в rootless Docker на одном VPS. Направление измерялось между контейнерными сетевыми точками. Rust-бинарники собраны по Cargo.lock в профиле dev, без шейпера, из исходников, соответствующих `7901221`. WebUI прошёл проверку типов и production-сборку Vite. Установщик с приватной сетью Prometheus проверен на ревизии `060d7c3`. Образы для launch загружались по digest из временного локального registry.

| Проверка | Фактический результат |
| --- | --- |
| [Туннель QUIC](tunnel.py) | TCP и UDP вернули случайную строку и адрес выхода сервера после NAT. Оба обмена повторились после рестарта ANet-сервера. Повторная инициализация сохранила профиль клиента. |
| [Подпись и доставка ревизии](../../../anet-server/src/probe_revision.rs) | Rust-тесты подтвердили привязку подписи к узлу, ревизии и целям, сохранность работающих целей при отказе и восстановление файла при повторной доставке. |
| [Регистрация, конкуренция и история](../../../anet-auth/tests/node_enrollment.py) | Одно приглашение при двух одновременных обменах дало один токен. Из двух публикаций от одной базы принята одна, вторая получила HTTP 409. Запоздавший ACK получил 409. На работающем узле применена ревизия 1, ревизия 2 отклонена локальным списком разрешённых адресов, ревизия 3 применена. Все три публикации видны в истории. |
| [Панель](../../../anet-webui/src/components/ProbeLinks.vue) | В Chrome пройдены вход, выбор узла, предпросмотр, публикация и получение подтверждения. Обзор показал доступную направленную связь. Измерение получено через Blackbox Exporter и Prometheus, возраст последней пробы меньше 45 секунд. Запрос графа без сессии получил HTTP 401. |
| [Правила мониторинга](../../monitoring/rules.test.yml) | Проверка через promtool прошла для перехода в отказ, восстановления и исчезновения устаревших данных. |

Эти результаты относятся к указанным образам приёмки. Рестарт в тесте относится к процессу сервера в контейнере. Для независимой проверки сочетания хостов, версии клиента или транспорта нужен прогон с этими параметрами.

Повторный запуск установщика сохранил байты `server.toml`, подписанную ревизию 3 и `targets.yml`.

При остановке auth сервер продолжал работать с тем же временем старта и прежними файлами целей. После возврата auth обновился heartbeat, сохранились ревизия 3/3 и сессия администратора. В отдельном испытании Blackbox Exporter потерял соединение только с целью TCP-пробы. При работающем heartbeat граф показал отказ со свежим измерением и вернулся в доступное состояние после восстановления соединения.
