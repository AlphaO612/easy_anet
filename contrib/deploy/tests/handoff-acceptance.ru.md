# Приёмка ANet Easy на linux/amd64

Объект проверки — ветка `anet-easy/server-image`. Каталог комплекта относительно рабочего репозитория — `../releases/anet-easy-amd64-flow-20261122/`. В комплект входят образы auth, WebUI, сервера, клиента, сетевого помощника, адаптера, профильного DNS, PostgreSQL, Prometheus, Blackbox Exporter и Grafana. Закрытые ключи с испытательных узлов в комплект не входят.

## Команды и откат

Сверка офлайн-комплекта из рабочего репозитория:

```sh
(cd ../releases/anet-easy-amd64-flow-20261122 && sha256sum -c SHA256SUMS)
python3 -m unittest discover -s contrib/deploy/tests -p 'test_*.py'
python3 -m unittest discover -s contrib/chain -p 'test_ingress.py'
```

Проверка unit-тестов дала 19 успешных и один пропуск в deploy, три успешных в chain. Длительные сценарии с контейнерами и сетевыми пространствами вызываются отдельно по ссылкам в таблице.

Для возврата маршрута перенесите сохранённые paths и profiles в черновик поверх действующей базовой ревизии и опубликуйте. Сравните отчёт входа и адрес у контрольного получателя. Для отката поставки используйте прежний проверенный комплект `../releases/anet-easy-amd64-8715d02/` и резервную копию до миграции в отдельном проекте. Возвращайте трафик только после проверки авторизации, ключей и фактического выхода восстановленного проекта.

## Незавершённые проверки

Выполнены проверка разрешённой конфигурации Compose для трёх профилей build и отдельная release-сборка изменённого auth. Полная последовательность чистых `build + launch` для всех трёх профилей требует завершения компиляции на выделенном стенде. Многоузловая матрица четырёх стратегий изолирована на одном физическом хосте, межсерверная передача в управляемой оркестрации использует QUIC.
