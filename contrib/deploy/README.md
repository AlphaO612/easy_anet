# Установка и эксплуатация

## На компьютере

**[Открыть руководство по установке на две VPS](distribution/START-HERE.md)**. В готовом комплекте это тот же файл `START-HERE.md`.

| Терминал | Перейти в каталог текущего выпуска | Передать комплект и войти в мастер |
| --- | --- | --- |
| Windows PowerShell | `cd "$HOME\Downloads\anet-easy-amd64-operator-20261122"` | `.\send-to-vps.ps1` |
| WSL | `Перейдите в папку комплекта на диске Windows через `/mnt/c/`` | `bash ./send-to-vps.sh` |
| Linux или macOS | Откройте терминал в папке полученного комплекта | `bash ./send-to-vps.sh` |

Если файлы уже переданы на первую VPS, войдите на неё по SSH, откройте удалённый каталог поставки и выполните `bash ./install.sh`. Для передачи вручную достаточно стандартных команд `ssh` и `scp`. [Команды и список файлов](distribution/START-HERE.md#2-если-хотите-передать-файлы-вручную)

## Git clone

Для обычной установки достаточно каталога поставки. Если хотите работать с исходниками, клонируйте ветку проекта **на компьютере**. Скопируйте SSH-адрес репозитория из меню **Code → Clone with SSH** вашего GitLab-проекта. В PowerShell выполните:

```powershell
$repo = Read-Host "SSH-адрес репозитория с веткой anet-easy/server-image"
git clone --single-branch --branch anet-easy/server-image "$repo" "$HOME\anet-source"
cd "$HOME\anet-source"
git branch --show-current
```

Ожидаемая ветка — `anet-easy/server-image`. Готовые образы поставляются отдельно в `images.tar`.

Из исходников можно подготовить тот же комплект для передачи. В **Bash на компьютере**, из корня клона, укажите каталог полученных образов в первом аргументе и новый каталог назначения во втором. В примере исходный комплект находится в каталоге загрузок пользователя:

```sh
python3 contrib/deploy/distribution/package.py \
  "$HOME/Downloads/anet-easy-amd64-operator-20261122" \
  "$HOME/anet-release" --local
cd "$HOME/anet-release"
bash ./send-to-vps.sh
```

## Панель и профили

Начальные профили создаёт SSH-мастер. Он сохраняет назначения, ключи и состояние проектов в приватных каталогах под `~/.local/state/anet-wizard`. Прерванную установку можно продолжить повторным запуском на том же VPS от того же пользователя. При входе по SSH как root мастер готовит пользователя `anet-vpn` для rootless Docker.

В панели стартовые профили доступны для скачивания администратору. Изменения управляемых профилей применяет агент входа после регистрации узлов и публикации топологии. В расширенном режиме доступны политики, группы, диагностика и балансировка. Для назначения нового пути и проверки результата используйте [руководство по управляемым профилям](docs/managed-flow.ru.md). Настройка измерений между узлами описана в [руководстве мониторинга](../monitoring/README.md).

## Установка из checkout и автоматизация

| Точка входа | Назначение |
| --- | --- |
| `install.sh` | Интерактивный SSH-мастер |
| `install.sh --help` | Параметры установки одного узла и штатных профилей |
| `compose.full.pre-builded.yml` | Полный состав сервисов с готовыми образами |
| `compose.full.build.yml` | Тот же состав с локальной сборкой компонентов |
| [Пример окружения](compose/example.env) | Адреса, привязки портов и лимиты |
| [Ansible](ansible/inventory.example.yml) | Inventory для установки из конкретной ревизии Git |

Для отдельного VPN-узла из уже доставленного комплекта выполните:

```sh
contrib/deploy/install.sh --install-docker --profile standalone \
  --bundle /srv/anet-release --host vpn.example.org
```

Для предварительной проверки одного узла `--config` подготавливает отдельный каталог состояния и проверяет Compose. Следующая команда использует параметры сборки и завершается до сборки или запуска сервисов:

```sh
check_dir=$(mktemp -d)
contrib/deploy/install.sh --config --mode build --profile webui \
  --host panel.example.org --state "$check_dir/node"
```

В режиме запуска через registry передайте `--release manifest.json` с digest образов. Для полного состава Compose требуются также параметры адаптера и приватный uplink. Практические примеры приведены в [руководстве по цепочке](docs/chain.ru.md) и [руководстве по входным протоколам](../chain/ingress.ru.md).

## Поставка и восстановление

Ветка содержит инструменты для упаковки и доставки. Владельцу выпуска нужны собственный адрес HTTPS, комплект образов соответствующей версии и исходный архив. Упаковщик формирует точную команду установки после указания адреса. [Подготовка выпуска](distribution/README.md)

Для резервной копии сохраните приватные каталоги состояния и данные PostgreSQL совместно. Для обновления существующих проектов сохраните имя проекта и каталог состояния.
