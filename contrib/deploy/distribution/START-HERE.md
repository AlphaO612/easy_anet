# Поставить VPN на две VPS с компьютера

**Начните на своём компьютере.** Подготовьте два SSH-адреса, два порта, имена пользователей и способ входа для каждой VPS. Откройте терминал **в папке поставки**, где лежит `images.tar`.

| Ваш компьютер | Одна команда для передачи и запуска |
| --- | --- |
| Windows, PowerShell | `.\send-to-vps.ps1` |
| Linux, macOS или WSL | `bash ./send-to-vps.sh` |

Помощник спросит адрес **первой** VPS, логин и порт, скопирует четыре файла по SSH и откроет удалённый мастер в этом же окне. При первом соединении сверьте отпечаток ключа сервера с данными провайдера. При первом входе OpenSSH запросит реквизиты. Помощник создаст на компьютере отдельный ключ Ed25519, добавит его публичную часть для root на первой VPS и проверит вход. Если входите обычным пользователем, для добавления ключа root потребуется sudo. Вход по паролю продолжит работать согласно прежним настройкам SSH.

## 1. Что находится в комплекте

| Файл | Где используется | Для чего |
| --- | --- | --- |
| `send-to-vps.ps1` / `send-to-vps.sh` | Ваш компьютер | Один помощник на выбор, по ОС |
| `install.sh` | Первая VPS | Проверяет комплект и открывает меню |
| `images.tar` | Первая VPS, затем вторая | 11 готовых Linux-образов, около 1,6 ГБ |
| `manifest.json` | Обе VPS | Идентификаторы и контрольная сумма образов |
| `source.tar.gz` | Первая VPS | Исходники и скрипты той же ревизии. Загрузчик распакует их сам |
| `START-HERE.md` | Ваш компьютер | Эта инструкция |

```text
Установка
Компьютер ── SSH, четыре файла ──► VPS 1 с панелью
                                     │
                                     └── SSH, мастер доставляет образы ──► VPS 2

После установки
Телефон ── WireGuard, VLESS или ANet ──► VPS 1 (вход) ── ANet ──► VPS 2 (выход) ──► Интернет
Браузер компьютера ── SSH-туннель ──► панель на VPS 1
```

Для этого примера обе VPS должны быть Debian или Ubuntu на amd64 с systemd и `/dev/net/tun`. Входите как `root` или обычный пользователь с sudo. Подготовьте на каждой VPS место под архив, распакованные образы и данные Docker. Для установки VLESS с автоматическим HTTPS понадобится домен, направленный на первую VPS. Мастер выпустит сертификат и установит nginx. Для WireGuard достаточно адресов VPS.

## 2. Если хотите передать файлы вручную

Эти команды заменяют помощник выше. Выполняйте их **на компьютере** из папки комплекта. В примере замените `root@203.0.113.10` на ваш логин и адрес первой VPS, а `22` — на её SSH-порт. Команды одинаковы в PowerShell, Bash и Terminal на macOS.

```sh
ssh -p 22 root@203.0.113.10 "mkdir -p -m 700 anet-release"
scp -P 22 install.sh images.tar manifest.json source.tar.gz root@203.0.113.10:anet-release/
ssh -t -p 22 root@203.0.113.10 "cd anet-release && bash ./install.sh"
```

**Вторая строка передаёт весь комплект одной командой.** Третья открывает терминал на VPS 1 и запускает мастер. Если вы уже вошли на VPS 1 отдельной SSH-сессией, выполните там `cd ~/anet-release && bash ./install.sh`. Для нового выпуска берите отдельный каталог.

Если Windows сообщает, что запуск сценариев запрещён политикой компьютера, используйте три ручные команды выше. Они выполняются в обычном PowerShell.

## 3. Что отвечать мастеру на первой VPS

| Что спрашивает мастер | Пример для первого WireGuard-профиля |
| --- | --- |
| Действие и настройки | Установить → рекомендуемые |
| Сколько выходных и входных VPS | 1 выход, 1 вход |
| Роль текущей VPS | Вход. Здесь же будет панель |
| Публичный адрес входа и SSH-порт | Реальный адрес VPS 1 и порт из панели провайдера |
| Сколько профилей каждого типа | WireGuard — 1, VLESS — 0, ANet — 0 |
| Адрес выхода, SSH-порт и логин | Реальные данные VPS 2 |
| Авторизация на VPS 2 | Пароль или SSH-ключ, доступный **на VPS 1**. Ввод пароля в SSH невидим |
| Предварительный план | Сверьте направление и порты. Разрешите порты в firewall провайдера и подтвердите |

Для этого примера откройте UDP 48000 на входе для клиентов и UDP 48000 на выходе для VPS 1. Если указали несколько профилей или другие порты, ориентируйтесь на напечатанный план. Панель по умолчанию слушает на `127.0.0.1:8088` первой VPS.

### VLESS с сайтом и бесплатным сертификатом

Если хотите VLESS, в таблице выше поставьте **WireGuard — 0, VLESS — 1, ANet — 0**. Для примера ниже выбран один входной профиль с рекомендуемым портом.

```text
                          ┌── TCP 80     проверка домена Let's Encrypt
vpn.example.org → VPS 1 ──┼── TCP 443    страница nginx для браузера
                          └── TCP 48000 VLESS/TLS → ANet → VPS 2
```

| Этап | Где | Что сделать |
| --- | --- | --- |
| 1 | Личный кабинет DNS | Создайте A-запись своего домена или поддомена с публичным IPv4 **входной** VPS. Если публикуете AAAA, она должна вести на IPv6 этого же входа. На время выпуска используйте прямое DNS-разрешение на VPS |
| 2 | Firewall провайдера и VPS | Разрешите входящие TCP **80** для проверки и продления, **443** для сайта и TCP-порт VLESS из плана. На выходной VPS разрешите UDP-порт ANet из плана |
| 3 | Мастер на VPS 1 | Выберите VLESS и **Let's Encrypt**, введите домен без `https://` и email для регистрации ACME. Готовые ключи доступны отдельным вариантом |
| 4 | Там же | Выберите **Студия**, **Журнал** или **GitHub**. Для GitHub введите логин публичного профиля. Мастер получит данные и сформирует страницу |
| 5 | Там же | Сверьте домен и порты в плане и подтвердите. Мастер настроит nginx, пройдёт проверку домена, установит сертификат и проверит HTTPS и TLS на порту VLESS |
| 6 | Ваш компьютер | Откройте в браузере `https://ВАШ-ДОМЕН/`. В VPN-клиент импортируйте ссылку VLESS из панели: она уже содержит домен, SNI и порт профиля |

**Проверка с компьютера.** Подставьте своё имя вместо `vpn.example.org`. Первая команда должна вернуть адрес входа. Вторая проверит доверие к сертификату, имя и ответ HTTPS. В Windows PowerShell используйте `curl.exe`, в Linux и macOS — `curl`.

```powershell
nslookup vpn.example.org
curl.exe -I https://vpn.example.org/
```

**Как проверить продление на входной VPS.** После выпуска сертификата мастер включает таймер Certbot. При продлении nginx перечитывает сертификат, а соответствующие VLESS-входы получают новую пару и перезапускаются.

```sh
sudo nginx -t
systemctl list-timers certbot.timer
sudo certbot certificates
```

В первой команде ожидается `test is successful`, во второй — следующий запуск `certbot.timer`, в третьей — ваш домен и дата окончания действия сертификата. [Продление и deploy-hook Certbot](https://eff-certbot.readthedocs.io/en/stable/using.html#renewing-certificates)

**Если выпуск остановился:** проверьте DNS с компьютера, правила TCP 80/443 и занятость портов. На входной VPS командой `sudo ss -ltnp` можно увидеть процессы, уже слушающие 80 или 443. После исправления продолжите сохранённую установку. Для HTTP-01 центр сертификации обращается к домену по TCP 80, поэтому этот порт нужен и при последующих продлениях. [Как работает проверка HTTP-01](https://letsencrypt.org/docs/challenge-types/#http-01-challenge)

## 4. В каком порядке всё выполняется

| Очерёдность | Где | Что происходит | Как увидеть результат |
| --- | --- | --- | --- |
| 1 | Компьютер → VPS 1 | Передача комплекта | `scp` показывает байты и скорость по каждому файлу |
| 2 | VPS 1 | Проверка SHA-256, распаковка исходников | Открывается меню ANet |
| 3 | VPS 1 | Ввод параметров | До применения видны входы, выходы и порты |
| 4 | VPS 1 → VPS 2 | Проверка SSH, подготовка rootless Docker и доставка образов | Статус называет текущий узел |
| 5 | Обе VPS | Запуск выхода, затем входа и проверка маршрута | Появляется путь к готовому клиентскому файлу |
| 6 | VPS 1 | Запуск панели и регистрация | Мастер печатает логин, путь к паролю и команду туннеля |

В мастере видны этапы **1/6 Поставка и топология → 2/6 Проверка плана → 3/6 Проверка доступа к VPS → 4/6 Подготовка узлов и доставка образов → 5/6 Запуск VPN и проверка маршрутов → 6/6 Панель и клиентские профили**. Для простого текстового меню запустите на VPS `bash ./install.sh --plain`.

Одна передача 1,6 ГБ занимает **около 2 мин 10 с при 100 Мбит/с** или **около 10 мин 40 с при 20 Мбит/с** без учёта накладных расходов. У мастера две линии связи с разной скоростью. Установка Docker и импорт образов добавляют время в зависимости от сети и диска VPS.

## 5. Открыть панель и подключить телефон

1. Сохраните напечатанные мастером команду туннеля и путь к файлу пароля. Если удалённый мастер завершился и вернул вас на компьютер, войдите на VPS 1 командой `ssh -p 22 root@203.0.113.10`, подставив свой адрес и порт. **На VPS 1** выполните напечатанную команду `cat` для чтения пароля. Чтобы снова увидеть точные команды и адрес, запустите мастер и выберите пункт доступа к установленной панели.
2. **На компьютере** откройте второе окно терминала. Вставьте команду из мастера. Для параметров примера это `ssh -N -p 22 -L 8088:127.0.0.1:8088 root@203.0.113.10`. Оставьте окно открытым.
3. **В браузере компьютера** откройте `http://127.0.0.1:8088`. Введите логин `admin` и пароль с VPS 1.
4. **В панели** откройте **Профили и маршруты → Профили мастера установки → Скачать профиль**. В строке профиля проверьте адрес назначенного выхода.
5. **На телефоне** импортируйте приватный файл через приложение WireGuard → «+» → импорт из файла. Для VLESS скопируйте ссылку из `.uri` в клиент VLESS/TLS. Для ANet откройте `.toml` в клиенте ANet. Включите VPN и проверьте публичный IPv4 через внешний сервис: для примера он должен совпасть с публичным адресом VPS 2.

## Если что-то остановилось

| Что вы видите | Где и что проверить | Как продолжить |
| --- | --- | --- |
| `Connection timed out` / `Connection refused` до меню | На компьютере выполните `ssh -p 22 root@203.0.113.10` со своими данными. Сверьте SSH-порт, сетевой firewall и состояние VPS | Повторите передачу после успешного SSH-входа |
| `Permission denied` для VPS 2 | Войдите на VPS 1 и оттуда проверьте `ssh -p ПОРТ ЛОГИН@АДРЕС_VPS_2` | Возобновите мастер под тем же пользователем |
| Ошибка контрольной суммы или отсутствует файл | Проверьте четыре файла из одного выпуска. На VPS место показывает `df -h "$HOME"` | Повторите команду `scp`, затем запуск |
| Сеанс SSH прервался после подтверждения плана | Комплект остался на VPS 1. Помощник напечатал команду возврата с именем удалённого каталога | Повторите **команду возврата** и выберите продолжение сохранённой установки |
| Вход запущен, маршрут до выхода не готов | Сверьте UDP-порт выхода и правила firewall VPS 2 с планом | Исправьте доступ, затем продолжите сохранённую установку |
| Браузер не открывает панель | Проверьте, что окно SSH-туннеля открыто. Если локальный 8088 занят, замените первое 8088 в `-L` на 8089 | Откройте `http://127.0.0.1:8089` при новом локальном порте |

### SSH остановился на этапе 3/6

Сообщение `Connection timed out during banner exchange` означает, что клиент вовремя не получил приветствие SSH. При таком сбое пароль ещё не проверялся. Проверьте соединение **с первой VPS**, с которой мастер подключается к остальным серверам.

1. **На компьютере** откройте команду возврата, напечатанную перед запуском мастера. Если нужна отдельная консоль для диагностики, войдите на первую VPS обычным `ssh -p ПОРТ ЛОГИН@ПЕРВАЯ_VPS`.
2. **На первой VPS** выполните диагностическую команду с экрана ошибки. Например, `ssh -v -o ConnectTimeout=15 -p 22 root@gw.example.org`. Подставьте SSH-адрес и порт недоступной VPS. Если ошибка повторилась, в консоли провайдера проверьте порт, правила доступа с IP первой VPS и состояние службы SSH. Если видите `Permission denied`, проверьте логин и реквизиты.
3. **В мастере** выберите повтор подключения или настройки проблемного сервера. Можно исправить адрес, порт, логин и способ входа, временно пропустить VPS или убрать её из плана. Перед сохранением проверьте показанные маршруты: профиль с отключённым входом или выходом будет пропущен целиком. Остальные профили сохранят свои номера и порты.
4. **После выхода** откройте тот же мастер под тем же пользователем и выберите продолжение сохранённого плана. Чтобы вернуть временно пропущенный сервер, откройте редактор плана, включите узел и подтвердите обновлённый план. Удаление из плана меняет последующие прогоны; уже работающие контейнеры и ключи остаются на VPS.

**Обновление прежнего мастера без повторной передачи образов.** На первой VPS перейдите в каталог, который помощник указал после передачи (например, `cd ~/anet-install.ABC12345`). Там должны лежать `images.tar` и `manifest.json`. Выполните одну команду:

```sh
curl --proto '=https' --proto-redir '=https' -fsSL https://github.com/AlphaO612/easy_anet/releases/latest/download/anet-easy-update.sh | bash
```

Обновление скачает только установщик и исходники, проверит совместимость с вашим манифестом и использует уже переданный архив. Запускайте его от того же пользователя первой VPS, чтобы открыть имеющийся план.

### Настроить ключ для первой VPS отдельно

Если архив уже на VPS, можно установить ключ с компьютера отдельно от передачи. При запуске укажите адрес первой VPS, SSH-порт и имя пользователя. Эти команды запускаются из папки нового комплекта:

| Терминал | Команда |
| --- | --- |
| Linux, macOS или WSL | `bash ./send-to-vps.sh --key-only` |
| Windows PowerShell | `.\send-to-vps.ps1 -KeyOnly` |

Закрытый ключ остаётся на вашем компьютере в `~/.ssh/anet-easy/<сервер>/<порт>/id_ed25519`. Помощник напечатает точную команду подключения. Старые ключи и способ входа по паролю сохраняются.

Для соединений между VPS мастер отдельно спрашивает SSH-пароль каждого активного удалённого узла до подключения. Нажмите Enter, если нужен вход по ключу. Введённые пароли используются только в текущем запуске и не попадают в сохранённый план. При возобновлении в новом SSH-сеансе введите их заново.
