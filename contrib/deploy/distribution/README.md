# Доставка одной командой

## Каталог для передачи по SSH

На компьютере откройте папку поставки и запустите один из помощников. Он спросит адрес, порт и пользователя первой VPS, передаст четыре файла по SCP и откроет мастер через SSH.

| На компьютере | Команда из папки комплекта |
| --- | --- |
| Windows PowerShell | `.\send-to-vps.ps1` |
| Linux, macOS, WSL | `bash ./send-to-vps.sh` |

Команды для ручной передачи, таблица этапов и подключение к панели находятся в [START-HERE.md](START-HERE.md).

Загрузчик проверит контрольные суммы трёх соседних файлов, распакует исходники в пользовательский каталог данных и откроет меню. Мастер читает архив образов непосредственно из каталога поставки. Используйте доверенную копию каталога и сохраните её для повторного запуска. Подготовьте такую поставку на машине издателя следующей командой.

```sh
python3 contrib/deploy/distribution/package.py "$ANET_IMAGE_BUNDLE" "$ANET_DISTRIBUTION" --local
```

## Запуск с HTTPS-сервера на первой VPS

Откройте интерактивный SSH-сеанс и выполните команду, которую прислал владелец поставки. В ней указан реальный HTTPS-адрес `bootstrap.sh` конкретного выпуска. Для закрытого каталога с HTTP Basic можно заранее записать реквизиты хоста в `~/.netrc` с правами 0600. Команда, которую печатает упаковщик, и загрузчик используют этот файл.

Загрузчик получает исходный архив установщика, манифест и готовые образы. Он сверяет SHA-256 каждого файла с данными из полученного по HTTPS скрипта, распаковывает установщик и открывает меню в SSH-терминале. Происхождение скрипта подтверждает доверенный HTTPS-хост издателя. Для запуска нужны Linux amd64, Bash, curl, tar, flock и sha256sum. Подробности о VPS и Docker приведены в [инструкции мастера](../README.md).

Комплект и исходники остаются в `~/.local/share/anet/releases`, либо в `$XDG_DATA_HOME/anet/releases`. Запланируйте место для архива образов и их копии в хранилище Docker. Повторный запуск той же команды использует полностью загруженный комплект. Рабочие конфиги и клиентские ключи мастер хранит отдельно.

## Подготовка поставки издателем

Работайте из checkout нужной ревизии. Подготовьте проверенный каталог с `manifest.json` и `images.tar` для полного профиля. Упаковщик использует образы из этого архива, поэтому изменения WebUI или сервисов должны уже входить в передаваемые образы. Для создания исходного комплекта служит [bundle.py](../scripts/bundle.py).

Присвойте `ANET_RELEASE_URL` фактический HTTPS-адрес нового каталога на своём сервере. В команде ниже `ANET_IMAGE_BUNDLE` указывает на каталог исходного комплекта, а `ANET_DISTRIBUTION` задаёт новый локальный каталог поставки.

```sh
python3 contrib/deploy/distribution/package.py "$ANET_IMAGE_BUNDLE" "$ANET_DISTRIBUTION" \
  --base-url "$ANET_RELEASE_URL"
```

По умолчанию упаковщик архивирует файлы коммита HEAD через git archive. Чтобы выбрать другую ревизию установщика, используйте `--ref COMMIT`. На диск записываются четыре файла. Разместите `bootstrap.sh`, `source.tar.gz`, `manifest.json` и `images.tar` в одном каталоге HTTPS-сервера по указанному адресу и передайте пользователю напечатанную команду.

Поставку этой ветки размещает её владелец. Исходный проект публикует собственные релизы. [Исходный репозиторий](https://github.com/ZeroTworu/anet) · [Релизы upstream](https://github.com/ZeroTworu/anet/releases)

## Обновление мастера в уже переданном комплекте

Войдите по SSH на первую VPS и перейдите в каталог прежнего комплекта, где находятся `images.tar` и `manifest.json`. Для выпуска с обновлением установщика выполните одну команду.

```sh
curl --proto '=https' --proto-redir '=https' -fsSL https://github.com/AlphaO612/easy_anet/releases/latest/download/anet-easy-update.sh | bash
```

Скрипт загрузит небольшой архив **конкретного выпуска**, проверит его и создаст подкаталог `anet-update-…`. В нём новый установщик использует прежние образы по ссылке. Перед запуском мастер проверяет контрольную сумму локального `images.tar`. Для повторного запуска используйте напечатанный путь к новому `install.sh`. Сохраните родительский каталог с образами, пока пользуетесь этим установщиком.

Если VPS работает без доступа к GitHub, передайте по SSH два файла одного выпуска и запустите из каталога прежнего комплекта `bash /путь/anet-easy-update.sh /путь/anet-easy-update.tar.gz`. При несовпадении манифеста скачайте обновление для своего комплекта или полную поставку нужного выпуска.

Издатель формирует оба файла из проверенного комплекта образов и указанного Git-коммита следующей командой. Переменная `TAG` задаёт точный тег GitHub Release, `ANET_UPDATE_DIR` — новый каталог для двух вложений.

```sh
python3 contrib/deploy/distribution/package.py "$ANET_IMAGE_BUNDLE" "$ANET_UPDATE_DIR" \
  --update --tag "$TAG" --ref "$COMMIT"
```

Добавьте `anet-easy-update.sh` и `anet-easy-update.tar.gz` к релизу с этим тегом. Обновление доставляет изменения установщика. Для изменений внутри контейнеров требуется выпуск с новыми образами.
